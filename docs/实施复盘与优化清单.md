## 1. 这次实际完成了什么

已完成一个可离线加载的 Chrome Manifest V3 扩展，目录是项目根目录下的 `jisilu-enhancer/`。它只在集思录的待发转债页运行，使用当前免费页面可见的行数据和公开行情接口：

- 在「配售10张所需股数(股)」后插入「10张所需金额」和「预估盈利 / 安全垫」两列；
- 主板/创业板/北交所按 100 股整手上取整；科创板按 200 股起、超出部分按 1 股递增；
- 金额显示实际买入资金、理论股数和一手金额；
- 使用「获配 10 张的预估总利润」计算满额和一手安全垫，并按 2/4/6/8% 着色；未填写利润绝不当作 0；
- 点击任一增强单元格打开设置抽屉，可存每债预估利润、限售比例、预估配售比例和备注；刷新后仍保留；
- 以「股权登记日」为潜伏截止日，已上市、已过登记日、未识别正股的行明确显示待补，不参与计算；
- 行情优先腾讯财经（一次批量请求取全页），兜底东方财富，最后回落到页面正股价；三者都失败时显示最近一次缓存并标注；
- 所有数据保存在 `chrome.storage.local`，没有账号、服务器或遥测。

## 2. 第一轮：发现并修复的问题

| 问题 | 后果 | 修复 |
| --- | --- | --- |
| `Number(null)` 会得到 `0` | 未填写预估盈利时会伪造 0% 安全垫 | 数值转换先显式识别 `null`、`undefined` 和空字符串；加入回归测试 |

| 页面是 SPA，可能反复重绘 | 容易反复插列、重复请求 | 使用 MutationObserver、防抖、`data-jisilu-enhancer` 标记、按股票代码去重 |

## 3. 第二轮：真实页面核对后的修复（本次）

第一轮是**按计划和经验推断**写的，本轮打开真实页面核对后，发现列名假设与现实不符：

| 问题 | 后果 | 修复 |
| --- | --- | --- |
| **页面根本没有「申购日期」列** | `subscriptionDate` 映射恒为 `-1`，过期判定永远返回 false，**已上市、已申购的行照样参与计算** | 改用「股权登记日」作潜伏截止日；新增 `core/dates.js`、`core/rules.js` 两个纯函数模块并补测试 |
| 「正股名称」别名放宽成「正股」 | 会命中「正股价」列，把股价当成正股名称显示 | 收紧为「正股名称」；测试断言 `stockName === -1` |
| 日期比较用浏览器本地时区 | 非 GMT+8 环境下会误判截止日，与 P0 计划要求的 Asia/Shanghai 不符 | `shanghaiToday()` 用 `Intl.DateTimeFormat` 取上海当天零点，可注入时间以便测试 |
| 东方财富在当前网络返回空响应 | 整页行情取不到，只剩页面价兜底 | 新增腾讯财经适配器：一次批量请求取全页、GBK 解码、北交所 `bj` 前缀；东财降为逐个兜底 |
| 北交所 92 开头未被识别 | 市场判断错误，整手规则跟着错 | 市场识别统一为 `688→科创板`、`300/301→创业板`、`4/8/92→北交所`，行情前缀与整手规则共用同一套判断 |

同时把原先埋在 IIFE 里、无法单测的逻辑（列名映射、日期判定、行情解析）抽成了纯函数，并用真实页面抓下来的 fixture 做回归。

## 3.5 第三轮：用户加载后「看不到效果」的修复（2026-09-07）

用户加载扩展后反馈「好像没啥用」。用无头浏览器把扩展代码注入真实页面并**测量渲染结果**（而非只看 DOM 文本），抓到两个致命 UI bug：

| 问题 | 根因 | 后果 | 修复 |
| --- | --- | --- | --- |
| **新增两列完全不可见** | element-ui 用 `<colgroup>` 给两个独立 `<table>` 定宽（`table-layout:fixed`），只插 `th/td` 不插 `<col>` | 实测新列宽度 **0px**，且位置超出表格宽度 1668 > 1652，被 `overflow:hidden` 裁掉 → 页面上**什么都看不到** | `ensureColumnWidths()` 给两个 colgroup 各插 2 个 `<col>`（136px/168px）并把表格加宽 304px；body wrapper 的 `overflow-x:hidden` 改为 `auto` |
| **多次重绘后列索引错位** | refresh 时表头已含插件插入的两列，`mapColumns` 对 27 列重算 → 索引整体 +2 | 过期保护再次失效（登记日已过的行读到了错误的单元格，照样算金额）；`股权登记日` 读到「网上规模」 | 列映射、表头定位、colgroup 定位、行提取全部**过滤 `data-jisilu-enhancer` 标记的单元格**，保证始终基于原始 25 列；补回归测试 |

配套改进：

- 「预估盈利 / 安全垫」未填时不再显示三个「待补」，改为蓝色虚线引导「点击填预估盈利」，点单元格即开设置抽屉 —— 此前用户完全不知道这列需要先填数才有值，这是「没啥用」感受的另一半原因。
- 首次使用在页面左下角显示一条可关闭的提示（说明两列在最右侧需横向滚动、点击单元格填预估盈利），关闭状态存 storage 不再骚扰。
- `chrome.runtime.sendMessage` 加 try/catch：后台休眠或报错时降级用页面正股价，金额列不再整体消失。
- manifest matches 补 `.../pre/` 与 `.../pre` 精确形式，防路径匹配差异导致脚本根本不注入。

**验证（无头浏览器实测，2026-09-07）**：注入后两列宽度 136px/168px、x=1082/1218（完全可见）；连续触发 4 次重绘后表头/表体均为 27 列不重复不错位；已上市行 → 待补，登记日 09-02 行 → 「已到或已过，不可潜伏」，登记日 `-` 行 → 正常算金额；截图复核提示条与两列渲染正常。单测 19/19 通过。

## 3.6 第四轮：真实 Chrome 中数据错位的修复（2026-09-07 晚）

用户加载修复版后截图反馈：两列**位置对了但数据全错**——金额列显示的是日期，登记日之后的数据整体左移 2 格。

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 表体单元格被 Vue 冲掉 | 新单元格插在行**中间**；集思录表格由 Vue(element-ui) 管理，页面数据刷新时 Vue 按位置回写自己 25 个单元格，把中间插入的单元格覆盖/挤掉 → 表头 27 列、表体只剩 25 列 → 错位 | **改为追加在整行末尾**（第 26/27 列）：Vue 只按位置管理前 25 格，末尾单元格永远不会被它的 diff 碰到。表头/colgroup 同样改为末尾追加 |
| 写入期间出现半更新状态 | 旧版「清理→异步取行情→写入」之间有 await 空窗，Vue 恰好在此重绘就会踩到缺格子的行 | 改为三阶段：①同步读取+清理 → ②异步取行情/设置（DOM 完全不动）→ ③一次性同步写入全部单元格 |
| 每行一次 `chrome.storage` 异步读 | 拉长异步窗口 | 改为整表读一次 `storage.read()`，在内存里合并全局/每债设置 |

同轮按用户要求把新增两列表头改为**深蓝底 + 琥珀金加粗**（`#0b1b34` / `#f5b64a`），与原生表头一眼区分；新增单元格加虚线左边框。

**验证（无头浏览器实测）**：连续 refresh + 模拟 Vue 位置回写（直接改写原始单元格文本）后，`股权登记日` 列数据仍各归其位（09-09 / 09-02），金额列正常计算（¥15,475 / ¥8,505），27 列不重不漏；注入真实 CSS 后表头渲染为深蓝金（实测 computed style）。单测 19/19 通过。

## 3.7 第五轮：自动预估盈利（两层模型，2026-09-08，v0.3.0）

老板要求把「预估盈利」这个唯一的手动输入也自动化。先读了三份估值资料（鹏元 2011 BS 分离法 / 浙商 2023 LSM 蒙特卡洛 / 中债 2023 蒙特卡洛+LSM）和已完成的 `bond-valuator/` 子项目（BSM + LSM 双引擎，16/16 测试通过），得出关键判断：

- **上市首日价格 ≠ 理论公允价值**。LSM 算的是「理性持有 6 年的完整期权价值」，系统性高于「首日抛售博弈价」（实测 CV=100 时 LSM≈122、现实首日≈110-120；2026 年 74% 新券首日顶格 157.30 更是 LSM 算不出的情绪价）。
- **正确合并**：经验曲线做「锚」（它本来就是对口的首日成交价反推），LSM 贡献「债底 / 强赎顶」两个边界（这是经验曲线给不了的）。

**实现**（新增 `core/predict.js`，纯函数可单测）：

| 层 | 内容 |
| --- | --- |
| 转股价值锚 | `CV = 正股价 ÷ 转股价 × 100`；基础溢价率随 CV 递减（CV<78 给 40%、CV≥125 给 0%，含债底/强赎凸性） |
| 规模修正 | <3亿 +10%、3~5亿 +4%、5~10亿 0、≥10亿 −2% |
| 评级修正 | 复用 bond-valuator 的评级→利差映射思路：AAA +3% … A −4%；未知评级不惩罚 |
| 情绪档位 | 保守 −3% / 中性 0 / 乐观 +5%，面板可切，默认中性 |
| 边界钳制 | 上市价夹在 `[债底(XNPV), 157.30涨停帽]` 之间 |

**接入**：`selectors.js` 加「转股价/评级」映射；`extractRow` 提取两字段；`writeCells` 当手填盈利为空时自动算中性档（显示 `~¥XXX · 自动预估`）；`panel.js` 加三档展示 + 情绪下拉；tooltip 展示三档 + 转股价值 + 债底。

**验证**：单测 **30/30**（新增 11 项 predict 测试，覆盖三档关系、债底托底、涨停帽、评级/规模分段）。真页注入实测：转股价/评级/规模正确提取，自动预估正常渲染（华纬 `~¥141`、润禾 `~¥164`），已上市/已过登记日正确拦截，面板三档展示 + 情绪切换正常。

**诚实点**：自动预估下的安全垫通常只有 1~2%（配债占用大资金、绝对收益小，这是真实特征，非 bug）；转股价发行前会按正股均价重定，导致转股价值变化，预测可能不准。

## 6. 维护规则

- 页面失效时，先修改 `config/selectors.js`，不要在业务逻辑中到处补选择器。
- 公式变更先修改 `core/` 并添加失败用例，再修改 UI。
- 列名、单位、日期口径以 `data-contract.md` 为准；页面改版先更新 fixture 再改代码。
- 不引入任何绕过付费、自动登录、抓取受限数据或云端上传能力。
- 每次修改后运行 `npm test`；涉及网页适配时补一次真实页人工验收并记录日期。
